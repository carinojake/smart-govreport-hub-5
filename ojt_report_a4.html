เรื่อง รายงานผลการฝึกปฏิบัติงานภาคปฏิบัติ (OJT) ประจำสัปดาห์ที่ 1

เรียน ผู้ควบคุมงานฝึกปฏิบัติงาน (OJT) / หัวหน้ากลุ่มงานเทคโนโลยีสารสนเทศ


๑. ต้นเรื่อง
ด้วย ผู้ปฏิบัติงานโครงการฝึกอบรม OJT มีความประสงค์ขอส่งรายงานผลการฝึกปฏิบัติงานภาคปฏิบัติ (On the Job Training: OJT) ประจำสัปดาห์ที่ 1 เพื่อรายงานสรุปผลการดำเนินงาน ปัญหา อุปสรรค และแนวทางการแก้ไข ให้ผู้ควบคุมงานได้รับทราบ

๒. ข้อเท็จจริง
ในการนี้ ผลการดำเนินงานปรากฏดังนี้ 1. ตรวจสอบและปรับปรุงระบบเครือข่าย Core Switch 2. ตั้งค่าระบบสำรองข้อมูล PostgreSQL บน Docker 3. ตรวจสอบความปลอดภัยเครื่องลูกข่าย จำนวน 15 เครื่อง 4. พัฒนา API เชื่อมต่อ Line ID และ 5. จัดทำคู่มือปฏิบัติงานมาตรฐาน (SOP) สำหรับปัญหาและอุปสรรคที่พบ ได้แก่ ตรวจพบสายแลนชำรุด จำนวน 1 จุด และเครื่องลูกข่ายติดมัลแวร์ จำนวน 1 เครื่อง ซึ่งผู้ปฏิบัติงานได้ดำเนินการแก้ไขเปลี่ยนสายแลนและทำการกักกันความเสียหาย (Quarantine) เครื่องลูกข่ายดังกล่าวเรียบร้อยแล้ว

การตรวจสอบและบำรุงรักษาระบบเครือข่ายคอมพิวเตอร์แม่ข่าย (Network Core Switch) และการกำหนดค่าเครือข่ายเสมือน (VLAN)
NET-02 		7.0 ชม.
(สะสม 7.0) 		1. ดำเนินการตรวจสอบสถานะการทำงานของระบบ Network Core Switch ชั้น 3 และตรวจสอบการกำหนดค่า VLAN ของกองทุนผู้สูงอายุ 2. ตรวจสอบจุดเชื่อมต่อสายสัญญาณภายในอาคาร พบข้อบกพร่องสายสัญญาณหลวมบริเวณห้องผู้อำนวยการ 3. ทำการตัดต่อและย้ำหัวสายสัญญาณ RJ-45 ใหม่ให้ได้มาตรฐาน 4. ทดสอบการเชื่อมต่อเครือข่ายด้วยคำสั่ง ping ไปยังหมายเลขไอพีเกตเวย์ 192.168.1.1 ผลการทดสอบสามารถใช้งานได้ปกติ Network Core Switch, อุปกรณ์ย้ำหัวสายสัญญาณ (Crimping Tool), สายสัญญาณ UTP, หัวต่อ RJ-45, และโปรแกรมทดสอบเครือข่าย (Command Prompt) ปัญหา: สายสัญญาณเครือข่ายหลวมและชำรุดบริเวณห้องผู้อำนวยการ ส่งผลให้การเชื่อมต่อติดขัด แนวทางแก้ไข: ทำการตัดต่อและย้ำหัว RJ-45 ใหม่ ทดสอบระบบจนสามารถใช้งานได้เป็นปกติ ✓ ผ่าน PDPA

DB-02 		7.0 ชม.
(สะสม 14.0) 		1. ตรวจสอบการทำงานของ PostgreSQL Container บน Port 5432 2. เขียนสคริปต์และกำหนดตั้งค่า Cronjob เพื่อการสำรองข้อมูลอัตโนมัติ 3. ประสานงานขอสิทธิ์ Root เพื่อแก้ไขข้อผิดพลาดสิทธิ์การประมวลผลของ Cronjob 4. ดำเนินการทดสอบการกู้คืนข้อมูล (Disaster Recovery Test) และตรวจสอบความถูกต้องของข้อมูล 100% Docker, PostgreSQL, Cronjob, Linux CLI ปัญหา: Cronjob ไม่สามารถทำงานได้เนื่องจากข้อจำกัดด้านสิทธิ์การใช้งาน (Permission Denied) / แนวทางแก้ไข: ประสานงานเจ้าหน้าที่ผู้ดูแลระบบเพื่อขอสิทธิ์ Root ในการรันกระบวนการสำรองข้อมูลและสอบทานผลการกู้คืน ✓ ผ่าน PDPA

SEC-01 		7.0 ชม.
(สะสม 21.0) 		1. ตรวจสอบ Audit Log และการตั้งค่าความปลอดภัยของเครื่องคอมพิวเตอร์ลูกข่ายจำนวน 15 เครื่อง ตามข้อกำหนด สกมช. 2. ดำเนินการแยก Segment VLAN (Network Isolation) เครื่องที่ตรวจพบมัลแวร์เพื่อป้องกันการแพร่กระจายไปยังระบบอื่น 3. ทำการสแกนระบบอย่างละเอียด (Full System Scan) เพื่อกำจัดมัลแวร์และสิ่งแปลกปลอมออกจากเครื่อง 4. อัปเดตฐานข้อมูลภัยคุกคาม (Antivirus Signature) ให้เป็นเวอร์ชันล่าสุดและตรวจสอบความปลอดภัยก่อนนำเครื่องกลับเข้าสู่ระบบเครือข่าย ระบบบริหารจัดการเครือข่าย (VLAN Management), ซอฟต์แวร์ป้องกันและกำจัดมัลแวร์ (Antivirus/Anti-Malware), เครื่องมือวิเคราะห์ Audit Log พบเครื่องลูกข่ายติด Malware โฆษณาจำนวน 1 เครื่อง แก้ไขโดยการแยก Segment VLAN เพื่อกักกันความเสียหาย ดำเนินการ Full Scan กำจัดมัลแวร์ และอัปเดต Signature ของระบบรักษาความปลอดภัยก่อนเปิดใช้งานตามปกติ ✓ ผ่าน PDPA
