### 2.2 การทดสอบกระบวนการไหลเวียนเอกสารและการอนุมัติ (Approval Workflow Testing)
- **การทดสอบสร้างกิจกรรม (Draft $\rightarrow$ Pending):** ผู้ฝึกงานกรอกข้อมูล กิจกรรมจะมีสถานะเริ่มต้นเป็น `pending` ทันที และไม่อนุญาตให้ผู้ฝึกงานอนุมัติงานของตนเอง
- **การทดสอบการอนุมัติ (Pending $\rightarrow$ Approved):** ผู้ควบคุมงานเข้าตรวจ ให้คะแนน 5 ดาว และเซ็นชื่อ ระบบเปลี่ยนสถานะเป็น `approved` และล็อคไม่ให้แก้ไข
- **การทดสอบการตีกลับ (Pending $\rightarrow$ Rejected):** ผู้ควบคุมงานระบุจุดบกพร่องและกดตีกลับ ระบบปลดล็อคให้ผู้ฝึกงานแก้ไขข้อความและส่งใหม่ได้ถูกต้อง

## บทที่ 3: ผลการทดสอบการเข้าถึงตามมาตรฐานสากล (Accessibility Testing - WCAG 2.1 AA)

| ข้อกำหนด (WCAG 2.1 AA) | รายละเอียดการทดสอบ | ผลการตรวจสอบระบบ Smart GovReport Hub | สถานะ |
| :--- | :--- | :--- | :---: |
| **1.4.3 Contrast (Minimum)** | อัตราส่วนความตัดกันของสีข้อความกับพื้นหลังต้องไม่ต่ำกว่า 4.5:1 สำหรับข้อความปกติ | ข้อความหลักใช้ `#0F172A` (Slate 900) บนพื้นหลังสีขาว (`#FFFFFF`) มี Contrast Ratio เท่ากับ **16.1:1** สูงกว่าเกณฑ์มาตรฐานมาก | **PASS** |
| **1.4.4 Resize text** | ข้อความต้องสามารถขยายขนาดได้ถึง 200% โดยที่เนื้อหาหรือฟังก์ชันไม่สูญเสีย | ออกแบบด้วย Relative Units (`rem`, `em`) และ CSS Flexbox/Grid หน้าจอจัดเรียงใหม่สวยงามเมื่อขยาย 200% | **PASS** |
| **2.1.1 Keyboard Accessible** | ฟังก์ชันทั้งหมดสามารถควบคุมได้ด้วยแป้นพิมพ์ (Tab, Enter, Space, Escape) โดยไม่ต้องใช้เมาส์ | สามารถใช้ปุ่ม `Tab` เลื่อนผ่านฟอร์ม, กด `Enter` เพื่อเลือกผู้ใช้และส่งแบบฟอร์ม, กด `Esc` ปิดหน้าต่าง Modal ได้สมบูรณ์ | **PASS** |
