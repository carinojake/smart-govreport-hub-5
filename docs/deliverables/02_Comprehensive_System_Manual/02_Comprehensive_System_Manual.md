## ส่วนที่ 1: การเตรียมความพร้อมและข้อกำหนดระบบ (Prerequisites)

### 1.1 ความต้องการด้านฮาร์ดแวร์และเบราว์เซอร์
ระบบ Smart GovReport Hub ได้รับการออกแบบให้ทำงานบนเว็บเบราว์เซอร์สมัยใหม่แบบ Responsive Web Application โดยไม่ต้องติดตั้งซอฟต์แวร์เสริมใดๆ ในเครื่องของผู้ใช้งาน:
- **เบราว์เซอร์ที่รองรับ:**
  - Google Chrome เวอร์ชัน 110 ขึ้นไป (แนะนำเป็นอันดับ 1)
  - Microsoft Edge เวอร์ชัน 110 ขึ้นไป
  - Mozilla Firefox เวอร์ชัน 115 ขึ้นไป
  - Apple Safari เวอร์ชัน 16 ขึ้นไป
- **อุปกรณ์ที่รองรับ:**
  - เครื่องคอมพิวเตอร์ตั้งโต๊ะและแล็ปท็อป (Desktop / Laptop) ความละเอียดหน้าจอแนะนำ $1366 \times 768$ ขึ้นไป
  - แท็บเล็ต (iPad, Android Tablet) รองรับการวาดลายเซ็นผ่านหน้าจอสัมผัส (Touch Screen)

### 1.2 การเข้าถึงระบบ (URL & Network Access)
- **Production URL (On-Premises / Server):** `http://localhost:8000` หรือ `https://govreport.agency.go.th`
- **Serverless Alternative (GitHub Pages):** `https://agency.github.io/smart-govreport-hub/`

## ส่วนที่ 2: การเข้าสู่ระบบและการยืนยันความยินยอม PDPA (Login & Consent)

### 2.1 การเข้าสู่ระบบด้วยรหัส PIN 6 หลัก
1. เปิดเว็บเบราว์เซอร์แล้วไปยัง URL ของระบบ
2. ระบบจะแสดงหน้าจอหลักและรายชื่อผู้ใช้งานพร้อมบทบาทหน้าที่
3. เลือกบัญชีของตนเอง หรือกดปุ่ม **"เข้าสู่ระบบ (PIN Login)"**
4. กรอกรหัส PIN ประจำตัว 6 หลัก (ตัวอย่างเริ่มต้น: ผู้ฝึกงานใช้ `123456`, ผู้ควบคุมงานใช้ `999999`)
5. กดปุ่ม **"ยืนยันเข้าสู่ระบบ"**

> [!NOTE]
> ระบบจำลองบัญชีเริ่มต้นสำหรับทดสอบ ได้แก่:
> - `usr_jake` (นายธนกฤต วิโรจน์กุล - ผู้ฝึกงาน)
> - `usr_may` (น.ส.เมทินี ศรีสวัสดิ์ - ผู้ฝึกงาน)
> - `sup_pm_it` (นายสุเมธ วิจิตรศิลป์ - ผู้ควบคุมงานด้าน IT)
> - `adv_prof_somchai` (ผศ.ดร.สมชาย ใจมั่น - อาจารย์นิเทศก์)
> - `adm_system` (นางสาวพัชราภรณ์ เทพารักษ์ - ผู้ดูแลระบบ)

### 2.2 การยืนยันนโยบายคุ้มครองข้อมูลส่วนบุคคล (PDPA Consent Modal)
เมื่อเข้าสู่ระบบครั้งแรก หรือเมื่อมีการอัปเดตนโยบายความเป็นส่วนตัว:
1. กล่องข้อความ **"หนังสือให้ความยินยอมการประมวลผลข้อมูลส่วนบุคคล (PDPA Consent Form)"** จะปรากฏขึ้นกึ่งกลางหน้าจอ
2. อ่านวัตถุประสงค์การจัดเก็บข้อมูล ซึ่งครอบคลุม:
   - การบันทึกและประมวลผลประวัติการฝึกปฏิบัติงาน
   - การจัดเก็บภาพถ่ายหน้างานเพื่อการตรวจรับงานทางราชการ
3. ทำเครื่องหมายถูกที่ช่อง **"ข้าพเจ้าได้อ่าน เข้าใจ และยินยอมให้ประมวลผลข้อมูลตามระเบียบ"**
4. กดปุ่ม **"ยอมรับและดำเนินการต่อ"**
5. ระบบจะบันทึก Log การยินยอมพร้อม Timestamp และ Signature Hash ลงสู่ฐานข้อมูลและไฟล์ `logs/pdpa_audit.jsonl` โดยอัตโนมัติ

## ส่วนที่ 3: คู่มือการใช้งานสำหรับผู้ฝึกงาน/ผู้ปฏิบัติงาน (Trainee Manual)

### 3.1 ภาพรวมหน้าจอและการติดตามชั่วโมง OJT สะสม 90 ชั่วโมง
เมื่อเข้าสู่ระบบในฐานะ Trainee หน้าจอจะแสดง **OJT Progress Bar** แบบไดนามิก:
- **ชั่วโมงที่บันทึกแล้ว (Logged Hours):** เช่น `24.0 / 90.0 ชั่วโมง` (คิดเป็น 26.7%)
- **แถบแสดงสถานะตามสี:**
  - สีส้ม: ยังไม่ผ่านการตรวจรับ (Pending Review)
  - สีเขียว: ผู้ควบคุมงานลงนามอนุมัติแล้ว (Approved)
- **สรุปจำนวนวันทำการ:** แสดงจำนวนวันที่บันทึกแล้วและจำนวนวันที่เหลือตามเกณฑ์

### 3.2 การบันทึกกิจกรรมรายวันและการสกัด SOP
1. เลื่อนลงมาที่ส่วน **"บันทึกการปฏิบัติงานรายวัน (Daily Logbook)"**
2. เลือกวันที่ปฏิบัติงาน (เช่น `5 กันยายน 2569`) และระบุสัปดาห์ (Week 1 - 4)
3. เลือกหมวดสมรรถนะ:
   - `IT-01`: งานบริการและสนับสนุนเทคนิคคอมพิวเตอร์
   - `GOV-01`: งานสารบรรณอิเล็กทรอนิกส์และเอกสารราชการ
   - `DATA-01`: งานบริหารจัดการข้อมูลและวิเคราะห์สเปรดชีต
   - `SEC-01`: งานความมั่นคงปลอดภัยสารสนเทศและการคุ้มครองข้อมูลส่วนบุคคล
4. กรอกจำนวนชั่วโมงการทำงาน (ค่าเริ่มต้น 7.0 ชั่วโมงสำหรับวันปฏิบัติงานปกติ)
5. ระบุเครื่องมือ ฮาร์ดแวร์ และซอฟต์แวร์ที่ใช้งาน (เช่น Microsoft Excel, e-Saraban, LAN Cable Tester)
6. บันทึกปัญหาและอุปสรรคพร้อมแนวทางแก้ไข (หากไม่มี ให้คงข้อความมาตรฐานว่า "ไม่พบปัญหาอุปสรรค การปฏิบัติงานดำเนินไปด้วยความเรียบร้อย")

### 3.3 การใช้งานระบบผู้ช่วยอัจฉริยะขัดเกลาสำนวนราชการ (AI Polish)
กรณีที่บันทึกกิจกรรมด้วยภาษาพูดหรือไม่แน่ใจในศัพท์ทางการ:
1. พิมพ์ข้อความบันทึกงานตามความจริงในช่อง **"บันทึกงานเบื้องต้น (Raw Input)"**
   - *ตัวอย่างข้อความดิบ:* "วันนี้ช่วยพี่ติดตั้งวินโดว์ใหม่ให้ฝ่ายการเงินแล้วก็สอนเขาใช้เอ็กเซลสรุปงบ เบอร์ติดต่อพี่เขา 081-234-5678"
2. กดปุ่ม **"✨ AI Polish ขัดเกลาภาษาราชการ"**
3. ระบบจะดำเนินการ 2 ขั้นตอนอัตโนมัติ:
   - **PDPA Auto-Masking:** ตรวจจับเบอร์โทรศัพท์และแปลงเป็น `[REDACTED_PHONE]` ทันที
   - **LLM Transformation:** แปลงสำนวนเป็นภาษาราชการตามระเบียบงานสารบรรณฯ
   - *ตัวอย่างผลลัพธ์:* "ดำเนินการติดตั้งและกำหนดค่าระบบปฏิบัติการ Windows สำหรับเครื่องคอมพิวเตอร์ลูกข่ายฝ่ายการเงิน พร้อมทั้งให้คำแนะนำเชิงเทคนิคการประยุกต์ใช้โปรแกรม Microsoft Excel ในการจัดทำรายงานสรุปงบประมาณ เพื่อสนับสนุนประสิทธิภาพการปฏิบัติราชการ"
4. ตรวจสอบความถูกต้องและกดปุ่ม **"นำไปใช้ในแบบฟอร์ม"**
5. กดปุ่ม **"บันทึกกิจกรรม"** เพื่อส่งให้ผู้ควบคุมงานตรวจสอบ

### 3.4 การสร้างและสั่งพิมพ์รายงานผลรายบุคคลขนาด A4
1. กดที่แท็บเมนู **"ออกรายงานราชการ A4 (Official GovReport)"**
2. ระบบจะรวบรวมข้อมูลกิจกรรมตลอดช่วงการฝึกงาน นำมาจัดเรียงในรูปแบบหน้ากระดาษ A4 มาตรฐาน
3. ตรวจสอบความสมบูรณ์ของข้อมูล:
   - ตราครุฑ 3.0 เซนติเมตรตรงกึ่งกลางหัวกระดาษ
   - ตารางสรุปเวลาแยกรายสัปดาห์
   - ช่องลงลายมือชื่อของผู้ฝึกงานและผู้ควบคุมงาน
4. กดปุ่ม **"🖨️ สั่งพิมพ์รายงาน (Print / Save as PDF)"** หรือกด `Ctrl + P` (หรือ `Cmd + P` บน Mac)
5. ในหน้าต่างพิมพ์ ให้เลือกปลายทางเป็น **"Save as PDF"** ขนาดกระดาษ **"A4"** และขอบกระดาษ **"Default"**

## ส่วนที่ 4: คู่มือการใช้งานสำหรับผู้ควบคุมงาน/พี่เลี้ยง (Supervisor Manual)

### 4.1 แดชบอร์ดตรวจสอบรายชื่อผู้ฝึกงานในสายงาน
1. เข้าสู่ระบบด้วย PIN ของ Supervisor (เช่น `999999`)
2. หน้าจอจะแสดงรายชื่อผู้ฝึกงานที่อยู่ภายใต้การกำกับดูแล พร้อมระบุ:
   - จำนวนชั่วโมงสะสม
   - สถานะการส่งรายงานของสัปดาห์ปัจจุบัน (ส่งแล้ว / รอตรวจ / ยังไม่ส่ง)
3. คลิกเลือกผู้ฝึกงานที่ต้องการตรวจประเมิน

### 4.2 การตรวจประเมิน ให้คะแนน 1-5 และบันทึกข้อเสนอแนะ
1. ตรวจสอบรายละเอียดกิจกรรมรายวันและขั้นตอน SOP ที่ผู้ฝึกงานบันทึกไว้
2. ในส่วน **"แบบประเมินผลการปฏิบัติงานประจำสัปดาห์"**:
   - เลือกคะแนนประเมิน (Rating Score):
     - `5` = ดีเยี่ยม (ผลงานเกินความคาดหมาย มีวินัยสูง)
     - `4` = ดีมาก (ผลงานถูกต้องตามมาตรฐาน สื่อสารดี)
     - `3` = ปานกลาง (ผลงานเป็นไปตามเกณฑ์มาตรฐาน)
     - `2` = ต้องปรับปรุง (มีข้อผิดพลาดเล็กน้อย)
     - `1` = ไม่ผ่านเกณฑ์ (ต้องได้รับการแก้ไขอย่างเร่งด่วน)
   - พิมพ์ข้อคิดเห็นของผู้ควบคุมงาน (Supervisor Comment) เช่น "มีความตั้งใจในการเรียนรู้งานสารบรรณและแก้ไขปัญหาเฉพาะหน้าได้ดี"
   - พิมพ์ข้อเสนอแนะเพื่อการพัฒนา (Development Advice) เช่น "ควรศึกษาคำสั่งและระเบียบกระทรวงเพิ่มเติมเพื่อความรวดเร็วในการออกเลขหนังสือ"

### 4.3 การลงลายมือชื่อดิจิทัล (Digital Canvas Signature)
1. ในช่อง **"ลายมือชื่อผู้ควบคุมงาน (Signature Canvas)"**
2. ใช้เมาส์หรือปากกาสไตลัส/นิ้วมือ (กรณีใช้ iPad/Tablet) เซ็นลายมือชื่อลงในกรอบสี่เหลี่ยม
3. หากต้องการเซ็นใหม่ ให้กดปุ่ม **"ล้างลายเซ็น (Clear)"**
4. ระบบจะทำการแปลงลายเซ็นเป็นรหัส Base64 Image ทันที

### 4.4 การอนุมัติและการตีกลับเพื่อแก้ไข (Approval & Revision Flow)
- **กรณีอนุมัติ (Approve):** กดปุ่ม **"✅ อนุมัติและบันทึกผลการประเมิน"** ข้อมูลกิจกรรมจะเปลี่ยนสถานะเป็น `approved` และถูกล็อคป้องกันไม่ให้ผู้ฝึกงานแก้ไข
- **กรณีสั่งแก้ไข (Reject/Revise):** พิมพ์เหตุผลในช่องข้อคิดเห็น แล้วกดปุ่ม **"🔄 ตีกลับให้แก้ไข"** ข้อมูลจะถูกปลดล็อคให้ผู้ฝึกงานกลับไปแก้ไขข้อความแล้วส่งใหม่อีกครั้ง

## ส่วนที่ 5: คู่มือการใช้งานสำหรับอาจารย์นิเทศก์ (Advisor Manual)

### 5.1 การเรียกดูภาพรวมผลการปฏิบัติงานและสมรรถนะ 4 ด้าน
1. เข้าสู่ระบบด้วยบทบาทอาจารย์นิเทศก์
2. เลือกรายชื่อนักศึกษาที่อยู่ในความรับผิดชอบ
3. หน้าจอจะแสดง **Competency Spider Chart / Bar Summary** แสดงสัดส่วนชั่วโมงที่ฝึกปฏิบัติในแต่ละด้าน:
   - ด้านโครงสร้างพื้นฐานไอที (IT Support)
   - ด้านงานสารบรรณภาครัฐ (e-Gov Workflow)
   - ด้านการบริหารจัดการข้อมูล (Data Management)
   - ด้านความมั่นคงปลอดภัยและ PDPA (Security & Compliance)

### 5.2 การบันทึกผลการนิเทศก์และให้ข้อเสนอแนะเชิงวิชาการ
1. ในหน้าสรุปการนิเทศก์ ให้บันทึกวันที่ลงพื้นที่นิเทศก์ หรือการนิเทศก์ผ่านระบบทางไกล
2. บันทึกผลการสัมภาษณ์ผู้ควบคุมงานและผู้ฝึกงาน
3. ลงลายมือชื่อรับรองการนิเทศก์ เพื่อประกอบการตัดเกรดหรือการให้หน่วยกิตการศึกษา

## ส่วนที่ 6: คู่มือการใช้งานสำหรับผู้ดูแลระบบ (Administrator Manual)

### 6.1 การจัดการบัญชีผู้ใช้งานและกำหนดสิทธิ์
1. เข้าสู่ระบบด้วยบทบาท `Admin`
2. ไปที่เมนู **"จัดการผู้ใช้งาน (User Management)"**
3. ผู้ดูแลระบบสามารถ:
   - เพิ่มผู้ใช้งานใหม่ (สร้าง User ID, กำหนดบทบาท และตั้งรหัส PIN เริ่มต้น)
   - รีเซ็ตรหัส PIN ของผู้ใช้งานกรณีลืมรหัสผ่าน
   - ระงับการใช้งานชั่วคราว (Deactivate Account)
   - ผูกความสัมพันธ์ว่าผู้ฝึกงานคนใด สังกัดอยู่ใต้ผู้ควบคุมงานท่านใด

### 6.2 การตรวจสอบ Audit Trail และสถิติการใช้งานระบบ
1. ไปที่เมนู **"บันทึกประวัติการใช้งาน (System Audit Log)"**
2. ระบบจะแสดงรายการเข้าใช้งานย้อนหลัง การกดยินยอม PDPA การแก้ไขข้อมูล และข้อผิดพลาดของระบบ
3. สามารถกดปุ่ม **"ส่งออกข้อมูลทั้งหมด (Export Database)"** เป็นไฟล์ Excel หรือ SQLite Backup เพื่อนำไปตรวจสอบภายนอก

## ส่วนที่ 7: คู่มือฝ่ายเทคนิคและการติดตั้ง (Technical Operations & Deployment)

### 7.1 การติดตั้งและรันระบบด้วย Python (Local / Server)

#### ความต้องการเบื้องต้น (Prerequisites):
- macOS (Apple Silicon M1/M2/M3) หรือ Ubuntu Linux 22.04 LTS
- Python 3.12 ติดตั้งผ่าน Homebrew หรือระบบหลัก
- บัญชี Google AI Studio API Key (สำหรับเรียกใช้ Gemini 1.5 Flash)

#### ขั้นตอนการติดตั้ง:
1. Clone หรือเปิดโฟลเดอร์โปรเจกต์:
```bash
cd /Users/jake/Documents/antigravity/beautiful-babbage
```
2. สร้างและเปิดใช้งาน Virtual Environment:
```bash
source /Users/Shared/my_ai_project/venv/bin/activate
```
3. ติดตั้งแพ็กเกจที่จำเป็น:
```bash
pip install fastapi uvicorn pydantic python-dotenv google-genai httpx
```
4. กำหนดค่าสภาพแวดล้อมในไฟล์ `.env`:
```env
GEMINI_API_KEY=your_gemini_api_key_here
DATABASE_PATH=ojt_logbook.db
PORT=8000
```
5. รันเซิร์ฟเวอร์:
```bash
python run_server.py
```
6. ทดสอบเปิดเบราว์เซอร์ไปยัง: `http://localhost:8000`

### 7.2 การติดตั้งระบบทางเลือก Serverless (Google Apps Script + Google Sheets)

สำหรับหน่วยงานที่ต้องการติดตั้งใช้งานฟรี 100% โดยไม่ต้องเปิดคอมพิวเตอร์เซิร์ฟเวอร์ทิ้งไว้:
1. สร้าง **Google Sheet** ใหม่ ตั้งชื่อว่า `OJT_Database_Master`
2. สร้างแท็บย่อย 4 แท็บ ได้แก่ `Users`, `Activities`, `Feedbacks`, `PDPA_Consents`
3. ไปที่เมนู **ส่วนขยาย (Extensions) $\rightarrow$ Apps Script**
4. คัดลอกโค้ดสคริปต์ Web App จาก `scripts/google_apps_script_backend.js` วางลงในตัวแก้ไข
5. ใส่ค่า `GEMINI_API_KEY` ใน Script Properties
6. กดปุ่ม **ทำให้ใช้งานได้ (Deploy) $\rightarrow$ รายการทำให้ใช้งานได้ใหม่ (New Deployment)**
   - ชนิด: เว็บแอป (Web App)
   - เรียกใช้งานในฐานะ: ตัวฉันเอง (Me)
   - ผู้มีสิทธิ์เข้าถึง: ทุกคน (Anyone)
7. นำ Web App URL ที่ได้ ไปกำหนดลงในไฟล์ `frontend/config.js` บน GitHub Pages เพื่อเริ่มใช้งานทันที
